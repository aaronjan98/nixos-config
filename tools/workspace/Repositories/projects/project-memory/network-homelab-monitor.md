# Project: Home Network Monitor (LANtern)

Status: incubation — router replacement must come first (provides OpenWrt data sources)
Resume tier: strong — demonstrates network systems, security, LLM integration, full-stack

---

## What it is

An open-source, self-hosted home network observability and control stack with a local LLM
layer for plain-English queries and anomaly explanation. Differentiated from existing tools
(ntopng, Zeek, Grafana stacks) by the conversational AI interface and per-device behavioral
modeling — using Ollama on sauron, no cloud dependency.

Intended as both a personal homelab tool and a public open-source project that others
can deploy.

---

## What makes it unique

No existing open-source project does all of this together:
- Device inventory with behavioral baseline per device
- Local LLM integration for natural-language queries ("Why did my TV lose internet at 8 PM?")
- Explanation-first anomaly alerts ("Device X made 47 DNS queries in 60 seconds — pattern
  resembles DNS tunneling or C2 beaconing")
- Conversational controls: "Block my TV until 9 AM" → translates to OpenWrt API call
- Weekly narrative network health reports generated by LLM

Commercial analogs (Darktrace, Cisco Secure Analytics) do similar things at enterprise
price points. No self-hostable equivalent exists.

## Architecture

### Data collection (runs on OpenWrt router, once Orbi is replaced)
- dnsmasq query logs → per-device DNS history
- netflow / conntrack export → per-device traffic flows
- ARP/DHCP events → device presence timeline
- OpenWrt conntrack → active connections

### Storage
- Prometheus: metrics (bandwidth, latency, device count)
- Loki: logs (dnsmasq queries, connection events, alerts)
- TimescaleDB or InfluxDB: time-series for speed tests, device presence history

### Processing agents
- Device inventory daemon: parses DHCP/ARP, resolves MAC → vendor (OUI database),
  maintains per-device profile (first seen, last seen, hostname, IP history)
- Baseline learner: tracks "normal" behavior per device (query volume, domains contacted,
  bandwidth patterns, active hours)
- Anomaly detector: flags deviations from baseline; feeds to LLM for explanation
- Speed test scheduler: runs LibreSpeed/Ookla on a schedule; stores history

### AI layer (Ollama on sauron)
- Query interface: natural-language questions → structured log/metric queries → LLM summary
- Anomaly explanation: raw event data + device profile → LLM generates human-readable alert
- Control parser: "block TV for 2 hours" → firewall rule via OpenWrt API
- Weekly report generator: pulls week's events → LLM narrative summary

### Controls
- Kick a device off the network (deauth + optional MAC block)
- Block a device from internet (firewall rule via OpenWrt API)
- Block a domain network-wide (dnsmasq rule)
- Set per-device bandwidth limits
- Wake-on-LAN for known devices

### Dashboard / UI
- Grafana for metrics visualization (bandwidth over time, device count, latency/packet loss,
  ISP speed history, top talkers)
- Custom web UI (FastAPI + lightweight frontend) for: device list, anomaly feed,
  conversational query interface, one-click controls
- Mobile-friendly — should work on phone as a quick-check tool

## Data sources enabled by OpenWrt (not possible with Orbi)

- Per-device real-time bandwidth (conntrack + tc)
- netflow export for full traffic flow analysis
- Packet capture for Suricata IDS (only worth running if mirroring traffic to sweetpea)
- Firewall rule API (LuCI/ubus — allows programmatic block/allow)

This is why router replacement is a prerequisite.

---

## IDS layer (Phase 2)

- Suricata running on sweetpea in IDS mode, mirroring traffic from OpenWrt
- Emerging Threats Open ruleset (free)
- JSON log output → Loki → Grafana
- LLM interprets alerts: "Suricata rule ET.TROJAN fired for device X — here's what this
  signature detects and why it triggered"
- Periodic nmap self-scan of the subnet: new open ports trigger alerts

## Build phases

### Phase 0 (prerequisite): Router replacement
- Get OpenWrt on RPi5; replace Orbi
- Enable dnsmasq query logging and netflow export in OpenWrt
- Confirm data flows to sweetpea

### Phase 1: Device inventory + internet health
- Parse DHCP leases → device presence database
- ARP scan on cron → catch static-IP devices
- Speedtest-tracker Docker container → ISP speed history
- Smokeping or continuous ping → latency/packet loss timeline
- Grafana dashboard: device list, speed over time, latency graph

### Phase 2: Per-device traffic + LLM queries
- netflow ingestion → per-device flow database
- dnsmasq query log → per-device DNS history
- Basic anomaly detection (volume thresholds)
- LLM query interface: "what happened at 8 PM?" → log query → Ollama summary

### Phase 3: Behavioral baseline + controls
- Baseline learner per device
- LLM anomaly explanation
- Control API: block device, block domain, set bandwidth limit
- Web UI for device list + controls

### Phase 4: IDS + open-source release
- Suricata integration on sweetpea
- LLM alert explanation
- Weekly report generator
- Polish Docker Compose, write public README, publish

## Homelab deployment

- Server-side stack: runs on sweetpea (Prometheus, Loki, Grafana, Speedtest-tracker, LLM agent)
- AI inference: sauron (Ollama, woken via WOL only when needed)
- Collection: OpenWrt router (RPi5)
- UI: reverse-proxied through sweetpea nginx, behind oauth2-proxy
