# 2026-06-04

- Added `scripts/update-all-pinned-packages.sh` to orchestrate the current pinned package updaters (`update-pi.sh` and `update-openai-codex.sh`).
- The orchestrator runs each child updater with `--no-build` and performs one final Nix build by default to avoid duplicate full-system verification builds.
- Updated `CONTEXT.md`, `README.md`, `docs/README.md`, `docs/SCRIPTS.md`, and `docs/PACKAGES.md` so agents and humans can discover the combined workflow.
- Fixed `scripts/update-pi.sh` cleanup trap: the EXIT trap referenced a local `tmp_dir` under `set -u`, which caused the script to exit nonzero after a successful update and aborted the orchestrator before later package updates could run.
- Fixed `pkgs/openai-codex/default.nix` for Codex 0.137.0's new tarball layout. The binary now lives at `vendor/x86_64-unknown-linux-musl/bin/codex` with sibling `codex-path/` and `codex-resources/`, so the derivation now installs the whole vendor tree and wraps the embedded binary from there.
- Hardened `scripts/update-all-pinned-packages.sh` so it reports which child updater failed, continues through the remaining updaters, and skips the final combined build if any child updater fails.
- Made `update-pi.sh`, `update-openai-codex.sh`, and `update-all-pinned-packages.sh` host-aware using the same hostname→flake mapping pattern as `nrs` (`nixos` → `thinkpad-t14`, otherwise use `$(hostname)` or `NIXOS_FLAKE_HOST` if set).
- Restored system `bubblewrap` and `ripgrep` on the wrapped `codex` PATH in `pkgs/openai-codex/default.nix`, which removes Codex's startup warning about missing sandbox prerequisites while still preserving the bundled vendor tree.
- Unpinned `nixpkgs-unstable` back to `github:NixOS/nixpkgs/nixpkgs-unstable`, updated `flake.lock` to `ffa10e26ae11d676b2db836259889f1f571cb14f` (2026-06-02), and verified successful `nrt`/`nrs` on the ThinkPad.
- Confirmed the old `primp`/`open-webui` blocker is gone on current unstable, and `opencode` is now at `1.15.13` in both the flake and the live system.
